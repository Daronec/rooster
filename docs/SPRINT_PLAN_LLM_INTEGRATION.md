# Спринт-план: Внедрение AI-ассистента в Rooster

> 14 спринтов (14 недель) с поэтапным внедрением Llama 3.2 on-device.

---

## Структура спринтов

### Фаза 1: Инфраструктура (Спринты 1–3)

#### Спринт 1 — Подготовка инфраструктуры
**Цель:** Настроить native-бэкенд для работы LLM

**Задачи:**
- [ ] Клонировать llama.cpp в `native/llama_cpp/` (git submodule)
- [ ] Создать FFI bridge header (`llm_bridge.h`)
- [ ] Создать FFI bridge implementation (`llm_bridge.cpp`)
- [ ] Добавить зависимости в `pubspec.yaml`: `ffi`, `path_provider`
- [ ] Настроить сборку Android через CMake (arm64-v8a)
- [ ] Настроить сборку iOS (static library)
- [ ] Создать каталог `models/` с README по скачиванию GGUF модели
- [ ] Unit-тесты на FFI bridge (mock-тесты)

**Результат:** Приложение собирается, native library линкуется.

---

#### Спринт 2 — Dart FFI bindings
**Цель:** Создать Dart-обёртку над native LLM

**Задачи:**
- [ ] Реализовать `LlmNativeBindings` (dart:ffi)
- [ ] Реализовать `LlmLibraryLoader` (платформенная загрузка)
- [ ] Создать контракт `ILocalLLMGateway`
- [ ] Создать реализацию `LocalLLMGatewayImpl`
- [ ] Добавить `localLLMGateway` в `AppScope`
- [ ] Инициализация LLM в `AppScopeRegister` (по флагу)
- [ ] Интеграционные тесты: загрузка модели на Android и iOS

**Результат:** LLM инициализируется и готова к генерации.

---

### Фаза 2: Базовые AI-функции (Спринты 4–6)

#### Спринт 4 — Авто-категоризация и теги
**Цель:** LLM автоматически предлагает теги и категории

**Задачи:**
- [ ] Создать промпт для категоризации задач
- [ ] Реализовать метод `extractTags(String text)` в gateway
- [ ] Добавить UI-подсказку тегов при создании задачи
- [ ] Интеграция с `TasksRepository` (сохранение тегов)
- [ ] Prompt engineering: оптимизация для 1B модели
- [ ] A/B тестирование качества тегов (100+ примеров)
- [ ] Unit-тесты на парсинг ответа LLM

**Промпт-пример:**
```
Ты — ассистент для категоризации задач.
Задача: "Купить молоко завтра утром"
Верни только JSON: {"tags": ["покупки", "еда"], "category": "Личное"}
```

**Результат:** При вводе задачи LLM предлагает релевантные теги.

**Задачи:**
- [ ] Создать промпт для определения приоритета
- [ ] Реализовать метод `determinePriority(String text)` в gateway
- [ ] Добавить UI-элемент выбора приоритета с AI-подсказкой
- [ ] Интеграция с `TaskEntity.priority`
- [ ] Prompt engineering: баланс high/medium/low
- [ ] Тестирование на 100+ примерах задач
- [ ] Unit-тесты на парсинг ответа LLM

**Промпт-пример:**
```
Определи приоритет задачи.
Задача: "Срочно исправить баг на продакшене"

```

**Результат:** При создании задачи LLM предлагает приоритет с объяснением.

#### Спринт 6 — Сжатие описания задачи

**Задачи:**
- [ ] Создать промпт для сжатия текста

**Промпт-пример:**
```
Создай краткий заголовок (до 50 символов) из описания.
```

### Фаза 3: Продвинутые функции (Спринты 7–10)

#### Спринт 7 — Умное создание задач (Natural Language → Structured)
**Цель:** Из естественного языка LLM извлекает все параметры задачи

**Задачи:**
- [ ] Создать промпт для извлечения параметров (дата, время, теги, приоритет)
- [ ] Реализовать метод `parseNaturalLanguage(String text)` в gateway
- [ ] Создать UI-экран "Умное создание задачи"
- [ ] Парсинг дат: "завтра в 18:00", "в пятницу", "каждый понедельник"
- [ ] Интеграция с созданием `TaskEntity`
- [ ] Prompt engineering для точного парсинга дат
- [ ] Тестирование на 200+ примерах естественного языка
- [ ] Error handling: если LLM не уверен — показать запрос уточнения

**Промпт-пример:**
```
Извлеки параметры из текста задачи.
Текст: "Напомни позвонить маме в воскресенье в 12:00"
Верни JSON: {
  "title": "Позвонить маме",
  "dueAt": "2026-09-07",
  "time": "12:00",
  "tags": ["семья"],
  "priority": "medium"
}
```

**Результат:** Пользователь пишет задачу естественным языком, LLM заполняет все поля.

## Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Модель 1B не справляется с сложными задачами | Высокая | Среднее | Использовать 3B модель, fallback на шаблоны |
| Нехватка RAM на старых устройствах | Средняя | Высокое | Graceful degradation, предупреждение |
| Долгое время генерации | Средняя | Среднее | Кэширование, оптимизация промптов |
| Ошибки парсинга JSON от LLM | Высокая | Низкое | Строгая валидация, retry-логика |
| Размер APK увеличивается на 500 МБ | Низкая | Низкое | Модель загружается при первом использовании |
