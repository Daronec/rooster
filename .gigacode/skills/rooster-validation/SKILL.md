# Проверки Rooster

Работай из корня репозитория. Этот навык описывает команды для установленных
инструментов, а не гарантирует успешность их запуска в каждой сессии.
Сведения о файлах проверены 2026-10-07; перед запуском сверяй текущую конфигурацию.

## Выбери SDK и область проверки

Прочитай `.fvmrc`, `pubspec.yaml`, `analysis_options.yaml` и `Makefile`.
`.fvmrc` сейчас указывает Flutter 3.41.6; Dart в PATH может принадлежать другой
версии Flutter. Проверь `command -v flutter`, `command -v dart`,
`command -v fvm`, затем версии доступного SDK. Если установлен FVM и доступна
версия проекта, используй `fvm flutter`/`fvm dart` вместо команд ниже.
Иначе укажи реально использованный SDK; не обновляй SDK ради запуска проверки.

Flutter wrapper может записывать cache даже при `--version`. При запрете
записи, отсутствующих пакетах или недоступной сети сообщи конкретный блокер;
не принимай такой сбой за дефект приложения и не меняй права/SDK-кеш.
Не считай недоступный MCP обязательным условием обычных CLI-проверок.

Проверь diff затронутых файлов. Начни с проверок изменённого поведения,
расширяй запуск при изменениях общей инфраструктуры или новых сбоях.

## Рабочие команды

Заменяй `<...>` реальными путями; не запускай placeholders буквально.
Для команд SDK здесь разрешён прямой вызов вместо отсутствующих make-целей.

| Цель | Команда | Когда применять |
| --- | --- | --- |
| Получить зависимости | `flutter pub get` | Изменён pubspec или зависимости ещё не разрешены; требуется доступ к пакетам |
| Проверить формат | `dart format --output=none --set-exit-if-changed <изменённые.dart>` | Не меняет файлы; проверяй только нужные исходники |
| Отформатировать | `dart format <изменённые.dart>` | Когда исправление форматирования входит в задачу |
| Анализ области | `flutter analyze <файл-или-каталог>` | Для локальной правки |
| Полный анализ | `flutter analyze` | Для общей архитектуры, DI, зависимостей и итоговой широкой проверки |
| Конкретный тест | `flutter test <путь_к_test.dart>` | Проверка изменённого поведения |
| Группа тестов | `flutter test test/features/tasks/` | Изменения task domain/data; выбери другую существующую группу при необходимости |
| Все тесты | `flutter test` | Общие изменения или подготовка коммита кода по правилам проекта |
| Покрытие | `flutter test --coverage` | Когда нужен отчёт о покрытии; не обязательный дубль каждого запуска |
| Генерация | `dart run build_runner build --delete-conflicting-outputs` | Routes, Freezed, JSON-аннотации, theme_tailor; команда есть в README |
| Проверка JSON ru | `python3 -m json.tool assets/flutter_i18n/ru.json > /dev/null` | Изменены русские переводы |
| Проверка JSON en | `python3 -m json.tool assets/flutter_i18n/en.json > /dev/null` | Изменены английские переводы |

Для JSON дополнительно сравни новые/изменённые ключи и placeholders между
локалями: синтаксическая проверка не доказывает их соответствие.
Для build_runner проверь изменения generated-файлов относительно исходного
состояния и не затирай посторонние правки. Generated-файлы не исправляй вручную.

## Существующие точки проверки

- Merge: `test/features/tasks/domain/services/task_remote_merge_policy_test.dart`.
- Миграция Hive-кодека: `test/features/tasks/data/mappers/task_entity_codec_migration_test.dart`.
- Хранилища: `test/features/tasks/data/repositories/budget_material_repositories_hive_test.dart`.
- Локальный LLM: `test/features/ai/local_llm_gateway_test.dart`.
- Тема widget-тестов: `test/helpers/test_app.dart` (`wrapWithAppTheme`).

В текущем pubspec есть `flutter_test`, но не объявлены `mocktail`,
`golden_toolkit`, `surf_widget_test_composer` и `integration_test`.
Не запускай инструкции из старых навыков так, будто эти пакеты уже доступны.
Unit/widget-тесты запускаются через `flutter test`, включая чистый domain.
Для новых integration-тестов сначала настрой зависимости и целевое устройство
в рамках задачи; hot reload не заменяет тест перезапуска процесса.

## Что не считать рабочей автоматизацией

- В Makefile только `chinese`, `tuna`, `official` — вызовы Windows `.cmd`
  для pub mirror. Это не команды анализа или тестирования для macOS.
- Нет make-целей `codegen`, `surfgen`, `format`, `intl_with_format`.
- В проверенном дереве нет каталога `scripts/`, поэтому вызовы
  `scripts/format.sh`, `scripts/check_coverage.sh`, `scripts/reset_goldens.sh`
  из старых инструкций не являются готовыми командами проекта.
- `tools/api_generator/dto_codegen.sh` и
  `tools/api_generator/request_codegen.sh` ссылаются на внешний
  `ekf.sales-flutter` и отсутствующий format-скрипт, а также выполняют clean.
  Не используй их для обычной генерации Rooster; адаптация требует отдельной задачи.

Если изменены только Markdown-навыки, проверяй их frontmatter, ссылки и
соответствие исходникам; Flutter-сборка для такой правки не нужна.
В завершении перечисли выполненные команды, результат и блокеры.
Различай исходные ошибки проекта, ошибки изменения и невозможность запуска;
не заявляй об успешной проверке без результата процесса.
