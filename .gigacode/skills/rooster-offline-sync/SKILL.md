# Offline-first синхронизация Rooster

Все пути ниже относительны корня репозитория. Проверяй текущий код перед
применением: сведения о сборке зафиксированы 2026-10-07 и могут измениться.

## Найди фактический путь данных

- Сборка хранилищ и executor: `lib/features/app/di/app_scope_register.dart`.
- Контракт очереди: `lib/core/sync/i_sync_queue.dart`; формат записи:
  `lib/core/sync/sync_operation.dart` и `lib/core/sync/sync_operation_type.dart`.
- Персистентная очередь: `lib/persistence/storage/sync_queue_storage/sync_queue_hive_storage.dart`.
- Отправка и повторы: `lib/core/sync/sync_manager_impl.dart`,
  `lib/core/sync/sync_backoff.dart`, `lib/core/sync/sync_manager_ref.dart`.
- Запись задач: `lib/features/tasks/data/repositories/tasks_repository_impl.dart`;
  сериализация: `lib/features/tasks/data/mappers/task_entity_codec.dart`.
- Конфликты: `lib/features/tasks/domain/services/task_remote_merge_policy.dart`;
  для планов — `lib/features/planning/domain/services/plan_remote_merge_policy.dart`.

В проверенной сборке подключён `NoopSyncRemoteExecutor`, возвращающий успех
без отправки. `SyncManagerImpl` при успехе удаляет операцию. Поэтому пустая
очередь и `idleSynced` сами по себе не подтверждают облачную доставку.
Наличие альтернативного executor на диске не означает, что он используется.

## Разбери нужную операцию

Проследи цепочку от repository до Hive, очереди, выбранного executor и
входящего merge. Запиши id сущности, id операции, revision, время изменения
и активного пользователя. Не предполагай, что payload содержит снимок:
`upsertTask` сейчас хранит только `taskId`, а удаление уже убирает запись Hive.
Проверь, что отправитель может корректно обработать оба случая.

Локальная запись и enqueue сейчас выполняются отдельными шагами. Между ними
есть напоминания и история изменений. При расследовании потери операции
проверяй исключения и остановку процесса на этих границах; не называй
процедуру атомарной без соответствующего механизма восстановления.

## Сохраняй нужные гарантии

- Повторная отправка после потерянного ответа должна быть безопасна.
  Проверяй идемпотентность по семантике серверной операции; UUID очереди
  сам по себе не доказывает дедупликацию на сервере.
- Очередь обрабатывается FIFO. Проверяй порядок create/update/delete,
  зависимые вложения и конкурентные enqueue/remove/update; Hive-очередь
  хранит список под одним ключом `operations` и переписывает его целиком.
- При `SyncAuthRequiredException` текущий drain прекращается, запись
  остаётся в очереди. Для обычных ошибок растёт attemptCount и применяется
  backoff. Проверяй возобновление после входа и смены сети.
- Не скрывай постоянную ошибку удалением операции и не запускай бесконечные
  ручные повторы. В тестах ограничивай число попыток и используй управляемый
  executor/время; реальный цикл останавливай после воспроизведения сбоя.
- Текущая task merge-политика сравнивает `updatedAtMillis`, затем
  `contentRevision`; при равенстве revision выигрывает remote. Сохраняй
  это поведение, если задача не требует его изменить. Отдельно проверяй
  локальные несинхронизированные изменения и запоздалый remote snapshot.
- Для удаления проверяй, не воскресит ли сущность последующий pull.
  Наличие tombstone или фильтра pending delete нужно подтвердить кодом.
- Проверь пользователя, которому принадлежит очередь. Текущие имена боксов
  общие (`tasks_v1`, `sync_queue_v1`); изоляцию аккаунтов нельзя предполагать.
  Не очищай реальные боксы пользователя для диагностики.

## Проверка результата

Выбирай сценарии по изменению: offline save → reload; ошибка → повтор →
успех; успешная отправка с потерянным ответом; update → delete; устаревший
remote; выход/вход другим пользователем; одновременные изменения очереди.
Закрытие и повторное открытие Hive проверяет сохранение в тесте; только
остановка и новый запуск приложения проверяют весь startup-путь.

Существующие образцы:
`test/features/tasks/domain/services/task_remote_merge_policy_test.dart`,
`test/features/tasks/data/mappers/task_entity_codec_migration_test.dart`,
`test/features/tasks/data/repositories/budget_material_repositories_hive_test.dart`.
Для новых queue/executor-тестов используй временные боксы и fake-зависимости.
Команды выбирай по соседнему навыку `../rooster-validation/SKILL.md`.
В отчёте различай локальное сохранение, прохождение fake-теста и подтверждённую
доставку на реальный backend; перечисли непроверенные границы.
