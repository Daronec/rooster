# Архитектурный анализ проекта Rooster — Задачи по исправлению

**Дата анализа:** 2026-10-20
**Статус:** Найдено 7 нарушений (4 критических, 3 средних)

---

## Сводная оценка

Проект демонстрирует хорошее понимание чистой архитектуры: feature-first организация, строгие интерфейсы репозиториев, Result/Failure паттерны, offline-first с Hive, чёткое разделение Screen/WM/Model. Однако обнаружены системные нарушения в области изоляции данных и SRP.

## КРИТИЧЕСКИЕ ЗАДАЧИ (Priority: P0)

### Задача 1: Утечка TaskEntity в презентационный слой

**Критерий:** Изоляция данных (Data Separation)
**Серьёзность:** 🔴 Критическое

**Проблема:** Доменная модель `TaskEntity` (30+ полей: `syncState`, `contentRevision`, `ownerUserId` и т.д.) напрямую попадает в UI через `ValueNotifier<List<TaskEntity>>`. При изменении доменной модели потребуется править все экраны.

**Места нарушений:**
- `lib/features/tasks/presentation/screens/tasks/tasks_model.dart:54-55` — `ValueNotifier<List<TaskEntity>> tasksListenable`
- `lib/features/tasks/presentation/screens/tasks/tasks_model.dart:60-61` — `ValueNotifier<List<TaskListEntity>> taskListsListenable`
- `lib/features/tasks/presentation/screens/tasks/tasks_wm.dart:35-38` — `pinnedTasksListenable`, `unpinnedTasksListenable`
- `lib/features/tasks/presentation/screens/task_detail/task_detail_model.dart:38-39` — `UnionStateNotifier<TaskEntity> detailState`
- `lib/features/tasks/presentation/screens/task_detail/task_detail_model.dart:44-45` — `ValueNotifier<List<TaskEntity>> subtasksListenable`

**Решение:** Создать ViewModel/DTO для передачи данных между слоями.

```dart
// lib/features/tasks/presentation/screens/tasks/task_item_vm.dart
final class TaskItemViewModel {
  final String id;
  final String listId;
  final String title;
  final bool isPinned;
  final TaskPriorityEntity priority;
  final DateTime? dueAt;
  // ... только поля, нужные для UI

  factory TaskItemViewModel.fromEntity(TaskEntity entity) {
    return TaskItemViewModel(
      id: entity.id,
      title: entity.title,
      isPinned: entity.isPinned,
      priority: entity.priority,
      dueAt: entity.dueAt,
    );
  }
}
```

Заменить `ValueNotifier<List<TaskEntity>>` на `ValueNotifier<List<TaskItemViewModel>>` и преобразовывать в Model слое.

### Задача 2: SRP нарушен — TasksRepositoryImpl является God Class

**Критерий:** SOLID — Single Responsibility Principle
**Серьёзность:** 🔴 Критическое

**Проблема:** `TasksRepositoryImpl` (~200 строк) выполняет 7+ обязанностей в одном методе `saveTask`:
1. Hive storage (CRUD)
2. Sync queue management
3. Analytics logging
4. Due reminder management
5. Task change history
6. Image upload enqueue
7. Schedule sync

```dart
// tasks_repository_impl.dart — saveTask
Future<void> saveTask(TaskEntity task) async {
  await _box.put(task.id, TaskEntityCodec.toMap(task));    // 1. Hive
  await dueGateway.upsertDueReminder(task);                 // 2. Reminder
  await historyWriter.addChange(...);                       // 3. History
  await _syncQueue.enqueue(op);                             // 4. Sync queue
  await task_image_upload_enqueue.enqueueTaskImageUploadIfNeeded(...); // 5. Images
  await analytics.logCreateTask();                          // 6. Analytics
  await _syncManagerRef.scheduleSync();                     // 7. Schedule
}
```

**Решение:** Вынести ответственности в отдельные сервисы данных:

```dart
// lib/features/tasks/data/services/task_persistence_service.dart
// Только Hive + SyncQueue

// lib/features/tasks/data/services/task_lifecycle_service.dart
// Только Reminder + History + Analytics + Images
```

### Задача 3: Презентация обходит Use Case слой

**Критерий:** Layered Architecture
**Серьёзность:** 🔴 Критическое

**Проблема:** `TasksScreenModel` и `TaskDetailScreenModel` напрямую вызывают методы репозитория, минуя use case слой:

```dart
// tasks_model.dart:177-181
Future<void> deleteTask(String taskId) => _tasksRepository.deleteTask(taskId);
Future<void> saveTask(TaskEntity task) => _tasksRepository.saveTask(task);

// task_detail_model.dart:96-102
Future<void> saveTask(TaskEntity task) => _tasksRepository.saveTask(task);
Future<void> deleteTask(String id) => _tasksRepository.deleteTask(id);
```

Создать use case для базовых операций:

```dart
// lib/features/tasks/domain/use_cases/delete_task_use_case.dart
final class DeleteTaskUseCase {
  Future<void> execute({required String taskId}) => _repository.deleteTask(taskId);
}

// lib/features/tasks/domain/use_cases/save_task_use_case.dart
final class SaveTaskUseCase {
  Future<void> execute({required TaskEntity task}) => _repository.saveTask(task);
}
```

### Задача 4: IAppScope — God Interface (ISP нарушение)

**Критерий:** SOLID — Interface Segregation Principle
**Серьёзность:** 🔴 Критическое

**Проблема:** `IAppScope` содержит 33 зависимости, что нарушает ISP. Клиенты вынуждены зависеть от всех 33, даже если нужна только одна фича.

```dart
// app_scope.dart — 33 property getter
abstract interface class IAppScope {
  Environment get env;
  ILogWriter get logger;
  IAuthGateway get authGateway;
  ITasksRepository get tasksRepository;
  IPlanningRepository get planningRepository;
  // ... ещё 29 зависимостей
}
```

**Решение:** Разделить на feature-scoped interfaces:

```dart
// Core scope — только инфраструктура
abstract interface class ICoreScope implements IDisposableObject {
  Environment get env;
  ILogWriter get logger;
  SharedPreferences get sharedPreferences;
  ITokenStorage get tokenStorage;
  IConnectivityGateway get connectivityGateway;
}

// Feature scope — наследуется от ICoreScope
abstract interface class ITasksScope implements ICoreScope {
  ITasksRepository get tasksRepository;
  ITaskListsRepository get taskListsRepository;
  ListTodayReadyTasksUseCase get listTodayReadyTasksUseCase;
}
```

## СРЕДНИЕ ЗАДАЧИ (Priority: P1)

### Задача 5: Отсутствие DTO для API бизнес-данных

**Критерий:** Изоляция данных
**Серьёзность:** 🟡 Среднее

**Проблема:** `lib/api/data/` содержит только служебные DTO (ErrorDto, ConstantsDto). Нет DTO для бизнес-объектов (TaskDto, PlanningDto). Бизнес-данные передаются через `TaskEntity` напрямую.

**Решение:** Создать DTO-классы для каждого бизнес-объекта и явный маппинг:

```dart
// lib/features/tasks/data/dto/task_dto.dart — Retrofit DTO
@JsonSerializable()
class TaskDto {
  final String id;
  final String title;
}

// lib/features/tasks/data/mappers/task_dto_mapper.dart
class TaskDtoMapper {
  TaskEntity toEntity(TaskDto dto) => TaskEntity(id: dto.id, ...);
  TaskDto fromEntity(TaskEntity entity) => TaskDto(id: entity.id, ...);
}
```

### Задача 6: SRP — фильтрация в Model вместо Use Case

**Критерий:** SOLID — Single Responsibility Principle
**Серьёзность:** 🟡 Среднее

**Проблема:** Фильтрация задач (убирает parent tasks и archived) происходит в `TasksScreenModel`, а не в Use Case:

```dart
// tasks_model.dart:104-115
tasksListenable.value = tasks
    .where((task) => task.parentTaskId == null || task.parentTaskId!.isEmpty)
    .where((task) => task.status != TaskStatusEntity.archived)
    .toList(growable: false);
```

**Решение:** Вынести фильтр в Use Case:

```dart
// lib/features/tasks/domain/use_cases/watch_active_tasks_use_case.dart
Stream<List<TaskEntity>> watchActiveTasks() {
  return _repository.watchTasks().map((tasks) => tasks
    .where((t) => t.parentTaskId == null)
    .where((t) => t.status != TaskStatusEntity.archived)
  );
}
```

### Задача 7: Naming — TaskEntityCodec vs Mapper Pattern

**Критерий:** Конвенции нейминга
**Серьёзность:** 🟡 Низкое

**Проблема:** Класс назван `*Codec` и реализован как static utility, тогда как архитектурный навык предписывает паттерн `*Mapper` с экземпляром для консистентности.

**Решение:** Либо привести к единому паттерну `*Mapper`, либо задокументировать, что `*Codec` — допустимый паттерн для Hive-сериализации (т.к. Hive требует статических методов для адаптеров).

| Принцип | Статус | Пример |
|---------|--------|--------|
| Feature-first | ✅ | `lib/features/<feature>/data/, domain/, presentation/` |
| Repository interfaces | ✅ | `ITasksRepository` в domain, `TasksRepositoryImpl` в data |
| Result/Failure паттерн | ✅ | `Result<T, F>`, `Failure`, `ApiFailure` |
| UnionState для UI | ✅ | `UnionStateNotifier<EmptyScreenBody>` |
| Naming: Entity suffix | ✅ | `TaskEntity`, `TaskListEntity`, `PlanningPlanEntity` |
| Naming: I*Repository | ✅ | `ITasksRepository`, `IBudgetRepository` |
| Naming: *UseCase | ✅ | `ListTodayReadyTasksUseCase` |
| Naming: *Screen/*WM/*Model | ✅ | 3-file convention |
| DIP: Constructor injection | ✅ | Все зависимости через конструктор |
| Offline-first | ✅ | Hive + SyncQueue + SyncManager |
