# План: Единый источник данных профиля пользователя

## Цель

Создать единый источник данных профиля (`UserProfileService`), который объединяет `AppAuthUserEntity` (auth identity) и `ProfileEntity` (cloud profile) в единый stream-based view, доступный из любой точки приложения через `IAppScope`.

## Текущее состояние

### Два разрозненных источника
1. **AppAuthUserEntity** — auth identity из OAuth (VK ID, Yandex ID). Хранится в FlutterSecureStorage.
2. **ProfileEntity** — cloud profile данные. Загружаются через IProfilePersonalDataGateway (сейчас Noop).

### Проблемы
- Нет единого view model для профиля пользователя
- Каждый screen инжектит gateways independently
- Desktop sidebar не показывает информацию о пользователе
- Нет автоматического обновления UI при смене данных

## Реализация

### Шаг 1: Создать сущность `UserProfile`

**Файл:** `lib/features/profile/domain/entities/user_profile.dart`

View model, который объединяет auth identity + cloud profile:
- `authUser` — AppAuthUserEntity (всегда при логине)
- `cloudProfile` — ProfileEntity? (null пока не загружен)
- Derived properties: `displayName` (cloud firstName > auth displayName > email > uid), `fullName`, `avatarUrl`
- `isProfileComplete`, `hasCloudProfile`

### Шаг 2: Создать `UserProfileService`

**Файл:** `lib/features/profile/domain/services/user_profile_service.dart`

Service, который:
- Слушает `IAuthGateway.authStateChanges`
- При логине пользователя загружает profile данные через `IProfilePersonalDataGateway.watchPersonalData(userId)`
- Мержит оба источника в единый `Stream<UserProfile>`
- Обрабатывает Noop gateway (возвращает `cloudProfile: null`)
- Предоставляет `currentAuthUser` и `currentProfile` для синхронного доступа

### Шаг 3: Зарегистрировать в `IAppScope`

**Файл:** `lib/features/app/di/app_scope.dart`

Добавить в интерфейс и реализацию:
```dart
UserProfileService get userProfileService;
```

### Шаг 4: Подключить сервис в DI

В месте создания `AppScope` добавить:
```dart
userProfileService: UserProfileService(
  authGateway: authGateway,
  profilePersonalDataGateway: profilePersonalDataGateway,
),
```

### Шаг 5: Миграция ProfileScreen

**Файлы:**
- `lib/features/profile/presentation/screens/profile/profile_model.dart` — убрать ValueNotifiers, оставить profile-specific операции
- `lib/features/profile/presentation/screens/profile/profile_wm.dart` — подписаться на `userProfileService.userProfileStream`, использовать `UnionStateNotifier<UserProfile?>`
- `lib/features/profile/presentation/widgets/profile_screen_body.dart` — заменить nested `ValueListenableBuilder` на `UnionStateListenableBuilder`

### Шаг 6: Миграция AuthScreen

**Файлы:**
- `lib/features/auth/presentation/screens/auth/auth_model.dart` — использовать `userProfileService.userProfileStream` вместо MergeStream двух gateways
- `auth_wm.dart` — без изменений (уже слушает `authStateChanges`)

### Шаг 7: Миграция Task-скринов

**Файлы:**
- `lib/features/tasks/data/gateways/auth_task_change_author_provider.dart` — использовать `userProfileService.currentProfile.displayName`
- `lib/features/tasks/presentation/screens/create_task/create_task_model.dart` — заменить `IAuthGateway` на `UserProfileService`

### Шаг 8: Desktop sidebar (опционально)

**Файл:** `lib/features/app/presentation/widgets/main_desktop_navigation_sidebar.dart`

Добавить секцию с аватаром/именем пользователя в bottom sidebar.

## Верификация

### Unit тесты
1. `UserProfile` — displayName precedence, fullName, copyWith, isProfileComplete
2. `UserProfileService` — loading state, content state, Noop gateway, logout

### Widget тесты
1. ProfileScreenBody — loading, content, not-signed-in state

### Ручная проверка
1. Запуск без логина → "Not signed in"
2. Логин через VK/Yandex → profile screen с данными
3. Create task → current user как author
4. Sign out → возврат на auth screen
5. Desktop sidebar (если фаза 5)

## Риски и edge cases

1. **Noop Gateway** — `watchPersonalData` возвращает `Stream.empty()`. Сервис должен обработать это и выдать `cloudProfile: null` (loaded but empty), а не зависнуть в loading.
2. **Stream disposal** — все screen-level subscriptions должны корректно отписываться в `WM.dispose()`.
3. **Local avatar** — остаётся отдельным (file path), не входит в unified profile.
4. **Teams gateway** — тоже Noop, остаётся отдельным, не затрагивается.
