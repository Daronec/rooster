# План: Внедрение VK ID и Yandex ID авторизации, удаление Sber ID

## Описание задачи

Полностью заменить текущую авторизацию через Sber ID на авторизацию через VK ID и Yandex ID согласно документации из `docs/social_auth_integration.md`.

## Текущее состояние

- Авторизация осуществляется только через Sber ID (cloud.ru backend)
- Используется `CloudRuAuthService` для обмена токенов на Yandex IAM token
- Все UI-компоненты привязаны к Sber ID
- DI-зависимости включают `ISberIdGateway` и `SberIdAuthGatewayImpl`
- В `pubspec.yaml` нет пакетов для VK ID или Yandex ID

## Целевое состояние

- Пользователь может выбрать вход через VK ID или Yandex ID
- Каждый провайдер имеет собственный gateway (`IVkIdGateway`, `IYandexIdGateway`)
- Общая стратегия авторизации поддерживает несколько провайдеров
- UI показывает обе кнопки входа
- Токены сохраняются в `FlutterSecureStorage`

## Архитектурные решения

### 1. Стратегия авторизации

Текущий `AuthBackendStrategy` расширяется до enum с тремя значениями:
- `vkId` — вход через VK ID
- `yandexId` — вход через Yandex ID

### 2. Gateway-паттерн

Каждый провайдер имеет свой интерфейс и реализацию:
- `IVkIdGateway` → `VkIdAuthGatewayImpl`
- `IYandexIdGateway` → `YandexIdAuthGatewayImpl`

Оба реализуют общий интерфейс `IAuthGateway` для состояния сессии.

### 3. Хранение токенов

- VK ID tokens: `oauth_vk_access_token`, `oauth_vk_id_token`
- Yandex ID tokens: `oauth_yandex_access_token`
- User data: `oauth_user_data`

### 4. UI-паттерн

- Экран входа показывает две кнопки: "VK ID" и "Yandex ID"
- Используются нативные кнопки провайдеров или кастомные
- Состояние загрузки для каждой кнопки независимо

## Риски и замечания

- VK ID SDK требует специфичного репозитория Maven для Android
- Yandex ID SDK требует FlutterFragmentActivity вместо FlutterActivity
- iOS требует обработки URL callback в SceneDelegate
- Необходимо настроить redirect URI в настройках приложений VK и Yandex
- Токены VK ID имеют срок действия, нужна реализация refresh logic
